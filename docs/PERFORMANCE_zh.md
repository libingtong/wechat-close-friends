# 性能设计与验收

## 原则

在保证隐藏与恢复语义一致的前提下尽量降低成本。功能正确性、宿主稳定性、个人数据保护是硬约束；「极致」不能靠省略出口过滤、禁用必要检查、抹掉异常或伪造基准实现。

## 路径预算

| 路径 | 设计预算 / 目标 | 测量与边界 |
|---|---|---|
| 单对象可见性查询 | 平均 O(1) 集合查询；只读快照，无阻塞锁和 I/O | 已规范化 ID 不主动创建对象；HashSet 不是最坏 O(1) 保证 |
| 普通搜索文本变化 | 边界索引去空白后，固定5字符比较；不 toString/substring | 常见无空白输入快速退出，最坏去空白 O(L)；不匹配时不分配 Runnable、不扫描视图、不读偏好 |
| 标题手势 | O(1) 计数/单调时钟/取消逻辑 | 不在触摸移动事件构建集合或刷新整页 |
| 入口定位 | 特定类初始化后一次；视图存活时幂等短路 | 不扫描全部 Activity/控件，不用周期定时器 |
| 名单/选项更新 | 后台 O(N) 生成不可变快照，单次原子发布 | 串行顺序、防丢更新；不按每条会话重复构建 |
| 名单渲染 | 复用行、按可见区域创建 UI | 不一次创建 N 个联系人 View |
| 多进程 | 无轮询的版本化更新，非每条消息 IPC | M1 未实现跨进程同步，列入 M3 验收 |
| 常驻工作 | 无网络、传感器和定时唤醒 | 按功能实际需要注册，离开生命周期释放 |

## 测试矩阵

- 名单规模：0、100、1,000、10,000；额外评估异常长 ID 和重复项。
- 查询：普通可见、隐藏、临显豁免、功能禁用、出口禁用、null/未知输入。
- 更新：连续增删、设置开关、临显后改名单、重隐、配置加载失败、并发读取/发布。
- 入口：普通输入、精确命令、命令前后缀、重复打开、控件重建、Activity 销毁。
- 手势：单击、多击、超时、长按、移动取消、长按后的抬手、原点击回调保留。

## JVM 基准方法

独立基准是开发反馈，不是 Android 性能证书。固定输入、先预热、多轮计时，输出每组中位耗时、查询次数和可核对的命中校验和。基准不在每次查询里调用计时器、不动态生成测试 ID、不产生测试日志。保留数据源和运行命令，不把一次最小值或优化器消除后的循环作为结论。

不要在普通单测里设「必须低于若干纳秒」这种受负载/JIT影响的易抖断言。正确性用稳定断言；时间趋势单独报告。JVM 测试不能证明 Android ART 下零分配、低功耗或不卡顿。

## 一加 13 真机门槛（候选目标，尚未测量）

- 可见性查询 p95 目标不超过 50μs；最终预算应按微信适配器整条调用链而非孤立 HashSet 设定。
- 高频过滤回调本项目代码不主动分配临时集合/字符串；通过 Android 分配采样核实，而不只靠代码阅读。
- 暖态入口定位不重复全树遍历；宿主页面重建允许一次重定位。
- 不出现本项目引入的主线程磁盘访问、周期后台唤醒或 Activity 泄漏。
- 同条件脚本滚动对比关闭模块 / 仅入口 / 开启隐藏的帧 p95/p99；不接受新增持续掉帧。
- 冷启动、内存和功耗先取基线，再设百分比门槛；尚无设备数据时不虚构数值。

以上是后续验收目标，不是本轮已达到的实测成绩。M1 未接入真实微信过滤链，不能用规则基准代替端到端测量。

## 优化顺序

先减少 Hook 范围和调用次数，再减少扫描/跨进程/磁盘工作，再处理分配和数据结构，最后才考虑微优化。每次优化均保留前后正确性与可逆恢复证据；对无法稳定测出的微小差异不增加维护复杂度。
