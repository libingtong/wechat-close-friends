# 微信密友 · InkVeil

**让亲密有边界，让隐私更从容。**

一个以本地隐私、轻量交互和低开销为目标的 Android / Xposed 微信隐私功能复刻项目。希望把名单管理、临时显示和快速重新隐藏放回熟悉的微信操作路径，而不是再增加一套繁重流程。

> **开发状态：M1 · `0.1.0-dev`，尚不可作为可用的微信隐藏工具。**
>
> **真实微信会话、通讯录、搜索结果、通知的过滤尚未接入。** 当前交付的是本地配置、内存规则、入口与手势代码。尚未完成真机验证，**没有微信版本兼容性结论**；编译成功、规则测试通过，不代表好友已经被隐藏。本仓库也不承诺已有可下载的 Release APK。

## 为什么做微信密友

- **交互留在微信里**：搜索命令、关怀模式入口，打开同一个宿主内原生设置面板。
- **性能从设计开始**：规则查询只读内存，配置变更在后台处理，不靠轮询换取“实时”。
- **配置尽量留在本机**：不接入原作者后台，不上传账号、联系人或消息内容。
- **适配宁缺毋滥**：无法确认目标结构时放行，不用宽泛 Hook 猜测界面和联系人。

这些是项目的设计约束，不是当前版本已完成全部隐私保护的承诺。

### 三条交互路径

1. **搜索进入设置**：在微信主页搜索栏输入 `#hide`，计划显示宿主内设置面板。命令区分大小写，允许首尾空白，普通搜索文本不触发。
2. **关怀模式进入设置**：微信「我 → 设置 → 更多 → 关怀模式」，长按「开启」。仅在已知页面找到唯一符合条件的「开启 / 開啟」按钮时绑定，不修改普通短按行为。
3. **标题快速切换**：多次点击首页标题「微信」，或长按标题。默认三击，相邻两击间隔须小于 800 ms；长按沿用系统标准时长。两种手势切换同一份“临时显示 / 重新隐藏”规则状态，**现阶段不是实际好友列表显隐**。

设置面板直接显示在微信宿主 Activity 内，不通过网页或跳转独立 App 承担上述入口。微信内两种设置入口及标题手势共享宿主进程配置和临时状态；独立 App 页面仅用于独立预览。

已知适配点来自原 App 的行为分析：关怀页面 `SettingsCareModeIntro`、搜索组件 `ActionBarSearchView`、首页 `LauncherUI`。标题只走已核实的固定字段链并校验文案与可见性，不扫描整个页面猜标题。不同微信版本可能改变这些结构；未知结构保持放行。

## 性能不是收尾优化

在不牺牲功能正确性的前提下，性能是每次修改都需要遵守的约束：

| 路径 | 约束 |
| --- | --- |
| 高频显隐查询 | 不可变 `HashSet` 快照，规范化标识后做精确匹配；通过原子引用读取当前快照 |
| 热路径开销 | 不读磁盘、不解析 JSON、不发网络请求、不打印逐条日志、不反射、不重建集合 |
| 配置更新 | 单后台执行器处理载入、序列化和持久化，完成后原子发布完整快照 |
| 界面与入口 | 原生控件、列表行复用、限定目标类的 Hook；幂等绑定，不轮询、不挂全局布局监听 |
| 手势处理 | 固定规模状态机，保存并链式调用原点击 / 触摸处理；状态变更入后台队列 |
| 搜索命令 | 直接读取 `CharSequence`，不创建字符串或子串；保留首尾空白兼容，空白扫描最坏为 O(L) |

`HashSet` 查询是通常情况下的常数时间预期，不是所有输入下的严格耗时保证。配置重建与持久化属于低频路径，不伪装成零开销。

项目提供 `:core:benchmark`，覆盖 100 / 1,000 / 10,000 条名单的可见、隐藏、临时显示、禁用场景。它只是主机 JVM 微基准与回归 smoke：**不能把主机上的纳秒结果当成 Android ART、微信帧率、耗电或真机延迟承诺**。真机验证还需覆盖帧时间、分配、冷启动、后台与大名单场景。

详见 [性能设计与测量边界](docs/PERFORMANCE_zh.md)。

## 本地隐私与使用边界

- 配置使用当前运行应用沙箱内的 `MODE_PRIVATE` 存储，不使用 world-readable 配置文件。
- 临时显示集合只保存在内存中，不持久化；支持立即重新隐藏与可选的后台重新隐藏。
- 本项目当前不实现账号 / 消息静默上报、追踪像素或原作者服务端通信。构建时仍需访问依赖与 Gradle 分发源。
- “离线”只描述本项目自身的设计，**不代表微信本身离线或没有网络通信**。
- 即使后续实现可见性过滤，隐藏也不等于删除、加密、擦除聊天记录，不能视为防取证或数据保密保证。
- 仅在本人可控的隔离测试设备与测试账号上验证。请勿使用日常账号承担未验证 Hook 的兼容性风险。

## 从源码构建

### 环境

| 组件 | 当前固定版本 |
| --- | --- |
| JDK | 17 |
| Gradle | 8.13 |
| Android Gradle Plugin | 8.13.0 |
| Android SDK Platform | 36 |
| Android SDK Build Tools | 36.0.0 |
| 最低 Android API | 24 |
| Xposed 编译 API | 82，`compileOnly` |

自行安装上述 SDK 包，并将 `JAVA_HOME` 指向 JDK 17、`ANDROID_HOME` 指向自己的 Android SDK。也可在仓库根目录创建不入 Git 的 `local.properties`，填写 `sdk.dir=你的SDK路径`；Windows 路径建议使用正斜杠。

构建不需要 Frida、Root 或已连接手机。运行微信宿主入口则需要本人可控测试机及兼容的 Xposed / LSPosed 环境；本项目尚未给出系统或微信版本兼容清单。

### Windows · PowerShell

在仓库根目录、已配置好 JDK 和 SDK 的终端执行：

```powershell
.\gradlew.bat :core:test :app:assembleDebug :app:lintDebug --no-daemon --console=plain
.\gradlew.bat :core:benchmark --no-daemon --console=plain
```

### Linux / macOS · Shell

```sh
sh ./gradlew :core:test :app:assembleDebug :app:lintDebug --no-daemon --console=plain
sh ./gradlew :core:benchmark --no-daemon --console=plain
```

Wrapper 固定 Gradle 8.13，并启用分发包 SHA-256 校验。首次执行需要下载官方分发包；本轮验证中首次下载因网络读取超时未完成，因此**没有声称 Wrapper 自举已通过**。实际构建验证使用本地已安装的 Gradle 8.13；若你已安装同版本，可将上述启动命令替换为 `gradle`。不要通过关闭校验来绕过下载问题。以上提供跨平台构建方式，不代表已在所有平台执行验证。

构建输出：

- 调试 APK：`app/build/outputs/apk/debug/app-debug.apk`
- 单元测试报告：`core/build/reports/tests/test/index.html`
- Lint 报告：`app/build/reports/lint-results-debug.html`

调试 APK 不是正式发布版本，调试签名也不是发布签名。`local.properties`、构建缓存和签名私钥不应提交。

## GitHub 在线编译

仓库提供 **Android构建** 工作流：推送 / PR 到 `master` 自动检查，也可在 **Actions → Android构建 → Run workflow** 手动运行。构建成功后，在该次运行底部 **Artifacts** 下载调试 APK、SHA-256 与构建信息的 ZIP；下载可能需要登录 GitHub，产物保留 14 天。

流水线会运行单元测试、Lint、Debug 构建，以及 APK 签名和对齐检查，不连接手机或账号，不把共享 Runner 的微基准当作性能门槛。**工作流配置不等于远端运行已成功，请以具体运行结果为准。** 当前不自动发布 Release，也不承诺正式签名或永久 APK 直链。

调试签名可能随 Runner 运行改变，不能保证覆盖安装上一调试版本；请勿为此卸载日常微信。操作步骤、产物说明与安全边界见 [在线编译指南](docs/CI_zh.md)。

## 参与开发

欢迎通过 Issue 提供需求、复现步骤和适配反馈。报告微信版本问题时，请提供：

1. 微信 `versionName` / `versionCode`、Android 版本、框架版本及模块版本。
2. 使用的入口、实际表现、期望表现及最小复现步骤。
3. **脱敏后的日志**；删除账号、wxid、联系人、消息正文、Token 与设备标识。

请勿上传聊天数据库、日常账号数据或第三方 APK。涉及适配的修改应给出可核对的类 / 方法证据、失败放行策略和测试；性能修改需要同条件前后对比，并说明测量平台与功能是否保持一致。不能以删除兼容行为来“优化”跑分。

提交改动前，请运行相关单元测试、Debug 构建和 Lint。新 Hook 应限定作用域、避免持有 Activity，并说明未知版本、生命周期变化和原监听器共存时的行为。
